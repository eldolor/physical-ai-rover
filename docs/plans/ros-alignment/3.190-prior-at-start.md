# 3.190 A cloud room prior asked once at a find's start, for targets the shipped prior does not know

*`PLAN-ros-alignment.md` section 3.190; index: [README.md](README.md).*

**Why.** The user, 2026-11-19: "What if we made a cloud call to find out
which room type a target is likely to be in, before starting a mission?",
then "Add it to the plan."

The `rooms` goal policy (3.96's F-large, the default since 3.125) orders
explore's goals by `prior[target][room type]`. The shipped prior
(`brain/explore_goal_rooms.json`) knows ten targets, all ProcTHOR floor
categories. A find's target is free text; any other target reads an empty
prior, every room type then reads as no type, and the policy runs as if the
map had no room labels at all.

**What is already known (recorded, not re-tested here):**

* **3.116.C built and measured the call, in the evaluation harness only**
  (`evaluations/room-prior-3116/llm_prior.py`; Opus 5.5, /room's model; one
  call per target, cached; a bad reply is no prior, never a guess). Standing
  in for the learned prior on the nine categories both know (588 test
  houses, mode R): found 573 vs 570, median goals 5 vs 4, mean reward 0.508
  vs 0.553, paired -0.045 [-0.095, +0.007]. Its criterion 9 ("no worse") met
  at the bar; criterion 8 (agreement) FAILED on cart and garbage can. The
  houses place objects by ProcTHOR's rules, which the learned prior was
  measured from, so that comparison favours the learned prior by
  construction.
* **Against no prior it has never been measured.** That is this feature's
  real comparison: an unknown target has no prior today, not the learned one.
* **20 of 20 everyday targets parsed** (3.116 criterion 10), and read as a
  person would look (knife kitchen 0.75, toothbrush bathroom 0.90).
* **Nothing in `brain/` or `control/` reads a cloud prior.** 3.116.C never
  left `evaluations/`.
* **The prior is inert without a room-label layer** (3.176.A): a find's map
  has room types only from a person's names on a saved map (3.160.D) or
  `find_room_labels` (off by default; labels hurt mode U by 0.080 reward in
  3.116.A).
* **The network knows four types** (kitchen, living room, bedroom,
  bathroom). A type outside them reads as no type (3.185's vocabulary maps
  the synonyms).

## Scope

* **One paid call at most, at a find's start**, and only when it can act:
  the job is a find, the policy is `rooms`, the target (lower case) is not
  in the shipped prior, and the mission has a room-label layer (a person's
  named rooms on the loaded saved map, or `find_room_labels` on). Otherwise
  no call is made and the status says why.
* **A config key, `find_prior_source`: `off` (default) | `cloud`**, in
  `config/robot.yaml` and `control/brain_config.py` together (CLAUDE.md
  section 6). Off is `dev`'s mission, exactly.
* **Cached** on disk by model id and target text, as 3.116.C: a repeat find
  of the same target pays nothing and needs no connection.
* **The reply is 3.116.C's shape, validated the same way:** one JSON object,
  the four types, each in [0, 1]. Anything else, a refusal, a timeout or no
  connection: the mission starts with no prior, as today, and the status
  records which (3.49: offline never blocks a start).
* **Bounded:** the call has a deadline inside `POST /mission/start`
  (`find_prior_timeout_s`, proposed 4 s; A fixes it). The start never waits
  longer, and the prior does not arrive mid-mission: a late reply is
  cached for the next find, not applied to this one.
* **It only reorders goals.** The rates go where the shipped prior's go
  (`RoomGoalPolicy`'s `prior`), for that mission only; the shipped file is
  never written. A typed room hint (3.176) is applied on top, so the hint
  wins. A prior never ends a search and never adds a goal.
* **A known target is untouched:** the ten shipped targets make no call and
  read the shipped prior.
* **Reported:** `status.room_prior = {source: shipped | cloud | cache |
  none, why, rates, model_id}`, in the mission report, and one line on the
  twin's mission card.

**What stays out.**
* Retraining F-large, or adding room types beyond its four.
* The label-asks decision (`find_room_labels`' flat-prior skip, 3.116
  amendment 7) stays on the **shipped** prior in this section, so a cloud
  prior never unlocks further paid calls. Whether it should is open
  question 1.
* A prior shown before Start. 3.176's parse route makes no paid call, and
  this section keeps that; the reading appears once the mission has started.
* The local VLM as the source (text-only questions were never measured on
  VE); a new section if wanted.

## Design (A may amend before any run)

* **The question and parser move out of the harness, unchanged:**
  `brain/room_prior.py` holds 3.116.C's prompt, the reply check and the
  cache; `evaluations/room-prior-3116/llm_prior.py` imports them, and a test
  pins that the cached 29 replies still parse to the same priors.
* **The call goes through the cloud vision service**, as every other paid
  call does: a new text-only route beside `/room`, bounded like it, with
  its route-guard entries (`tests/test_serverless_routes.py`) and its
  template change. The brain reaches it as it reaches `/room`. The Lambda's
  deploy is the user's.
* **The model is /room's** (Opus 5.5, the one measured). Another model
  (the user raised Claude Fable 5.2 on 2026-11-19) is an arm in B, only
  after a real `converse` call confirms its id and region, and it replaces
  the default only by B's numbers.
* **Wiring:** `brain_server` decides whether a call can act and makes it;
  `MissionRunner` takes the rates as a start argument, like `room_hint`,
  and hands them to explore's goal choice. No new movement path, no change
  to who drives.

## Criteria (written 2026-11-19, before any code or run; CLAUDE.md section 7)

**A, free: the cloud prior against no prior, from 3.116.C's cached replies**
(no new call). F-large, the stand-in labeller, mode R, the 588 test houses
(their fourth read: 3.96 C, 3.116 A and C used them; recorded, and no arm
here is selected on them). Three arms on one commit: **cloud** (3.116.C's
rows, re-run), **none** (the target's prior withheld, which is what an
unknown target gets today), **wrong** (the cloud's rates with its highest
and lowest types swapped).

1. **Progress:** paired mean reward, cloud minus none, has its 95% interval
   (10,000 draws over houses) **above 0**, and the cloud arm's median goals
   are <= none's.
2. **Stability, finds:** cloud finds >= none's finds minus 1%.
3. **Stability, a wrong prior:** the wrong arm finds >= none's minus 2%,
   and its median metres are <= 1.25 x none's. If this fails, C does not
   start until the user has seen the number.

**B, paid (cents; a 2-call pilot reports the real figure first; the whole of
B stops at $2):** a fresh set of 40 everyday targets, none in the shipped
prior and none among 3.116.C's 20 (the prompt was written with those in
view), pinned in a test before the first call. For 20 of them one expected
room type is written down with the set (the unambiguous ones); the author
of the set is the author of this section, which is recorded with the result.

4. **Valid replies:** >= 38 of 40 parse to a prior.
5. **Sensible:** the top type matches the written one on >= 18 of the 20.
6. **Informative:** >= 30 of 40 pass `prior_is_informative` (a flat reply
   changes nothing, so it is the measure of how often the call can help).
7. **Another model, only on the user's go:** the same 40 under it; it
   replaces the default only if it meets 4-6 and beats Opus 5.5 on
   criterion 1's arm run with its replies for the nine categories.

**C, the wiring, behind the key:**

8. **Off is off:** with `find_prior_source: off`, 0 of 200 missions differ
   from `dev` on the selection houses, both modes (outcome, goals, metres).
9. **The wired path is the measured one:** with the key on and the cache
   holding 3.116.C's replies, missions through `MissionRunner` match A's
   cloud arm on the selection houses: 0 differences.
10. **One call, and only when it can act** (tests): a shipped target, a
    survey, the `rule` policy, or no room-label layer makes 0 calls; a cache
    hit makes 0; anything else makes exactly 1.
11. **A failed call costs nothing but its deadline:** with every connection
    refused, a reply that is not the JSON, and a reply past the deadline,
    the start returns within the deadline plus 0.5 s, the mission runs with
    no prior, and `status.room_prior.why` names the cause.
12. **The hint wins:** with a typed `room_hint`, the goals are the hint's
    with or without a cloud prior for the other types set to 0 (test).
13. The new route's guards pass, and the vision service's own suite covers
    the route (a valid reply, a malformed one, a model error).

**D, through the live stack and on the page:**

14. One find on the live local stack through the brain's HTTP API, on
    `home_first_floor` with rooms named on a saved map, for a target outside
    the shipped prior: `status.room_prior.source` is `cloud` on the first
    run and `cache` on the second, the mission is found with 0 contacts, and
    its first goal lies in a room of the prior's top type.
15. A phone-size screenshot of the mission card's prior line, in operator
    mode, for a cloud prior and for none.

**E, the Rover:** in a real house the comparison is 3.116.D's (open, on the
Rover); this section's arm joins it: finds of household targets with the
key on and off, bars written there before the runs.

A failed criterion is recorded as failed, not re-scoped.

**Amendment 1 (2026-11-19, A, before any run): how criteria 1-3 are
measured, and B's set.**

* **Harness:** `evaluations/room-prior-3190/arms.py` (`run OUT`, then
  `score OUT`), built on 3.116.C's `c9.py`: `T.mission(split, house, "R",
  spec, 0, drop, labels)` with `ask._spec("stand-in")`, i.e. F-large's
  `best.json` greedy over `room_features` with the stand-in labeller and
  every label kept -- the path 3.116.C measured, with the prior read from
  `T.PRIOR[target]` exactly where the shipped prior is read. The stand-in
  labeller exists only in the harness; that the wired `RoomGoalPolicy`
  reads a prior the same way is C's criterion 9, not assumed here. The
  houses are `c.test_houses()` (train 1000-1999, usable: 588; 583 with a
  mode-R target, all nine of 3.96's categories). 4 workers, one commit.
* **The arms**, each set per worker by the pool's initializer, as `c9.py`:
  * **cloud:** `T.PRIOR` holds the parsed rates in
    `evaluations/room-prior-3116/llm_prior.json` (`us.anthropic.claude-opus-5-5`)
    for the nine categories. A category with no parsed reply stops the run.
  * **none:** the nine categories are removed from `T.PRIOR`, so the target
    reads `{}`: every candidate's `prior` and `prior_new` are 0, as an
    unknown target's are today.
  * **wrong:** the cloud's rates with its highest and lowest types swapped.
    **Ties** are broken by the key order kitchen, living room, bedroom,
    bathroom (the first maximum and the first minimum), 3.116's scorer's
    rule. Written out now (kitchen / living / bedroom / bathroom):
    basketball 0.02 / 0.06 / 0.005 / 0.10; box 0.30 / 0.40 / 0.50 / 0.55;
    cart 0.04 / 0.05 / 0.15 / 0.06; dog bed 0.07 / 0.02 / 0.15 / 0.22;
    garbage bag 0.10 / 0.55 / 0.12 / 0.30; garbage can 0.30 / 0.85 / 0.50 /
    0.85; house plant 0.35 / 0.15 / 0.25 / 0.50; laundry hamper 0.55 /
    0.06 / 0.03 / 0.40; plunger 0.03 / 0.55 / 0.01 / 0.01. **Recorded:**
    garbage can's reply ties kitchen and bathroom at 0.85, so its wrong
    prior still holds bathroom at the top (tied with the living room);
    garbage can is 149 of the 583 missions, so the wrong arm is milder than
    a full swap on a quarter of them. The rule is kept, not tuned.
  * Every row records the arm and the prior it read; the scorer refuses a
    file whose rows read another arm's prior (as `c9.py`).
* **The numbers:** found = outcome `found`; median goals and median metres
  over found missions; reward per mission as 3.65's (exceptions count
  `-CRASH_COST`), over all 583. **Paired** reward = per-house cloud minus
  none (or wrong minus none), mean over the 583, interval the 2.5th and
  97.5th percentiles of 10,000 bootstrap means over houses (numpy
  `default_rng(0)`).
* **The bars, as numbers:** criterion 1: the paired interval's low end > 0
  **and** median goals(cloud) <= median goals(none). Criterion 2:
  found(cloud) >= 0.99 x found(none). Criterion 3: found(wrong) >= 0.98 x
  found(none) **and** median metres(wrong) <= 1.25 x median metres(none).
* **Not criteria, reported:** the cloud arm against 3.116.C's own
  `c9/llm-R.json` rows (how many of 583 differ in outcome, goals or metres:
  the harness's determinism across commits); per-category paired reward;
  wrong minus none's paired interval.
* **B's 40 targets, fixed now** (`evaluations/room-prior-3190/targets.py`,
  pinned by `tests/test_room_prior_set_3190.py`): none is a key of the
  shipped prior or among 3.116.C's 29 targets, and none is a near-synonym
  of one (no remote, pillow, book or charger variants). The author is the
  author of this section (a Claude session, 2026-11-19), recorded as
  criterion 5's caveat. **With an expected type (20):** kitchen: spatula,
  cutting board, oven mitt, dish soap, kettle; bathroom: toilet paper,
  shampoo bottle, bath mat, toothpaste, razor; bedroom: alarm clock,
  pajamas, jewelry box, duvet, slippers; living room: video game
  controller, board game, sofa cushion, dvd case, fireplace poker.
  **Without (20):** coffee mug, scissors, tape measure, flashlight,
  notebook, pen, sunglasses, wristwatch, tablet, baseball cap, jacket, dog
  leash, candle, tissue box, blanket, hairbrush, medicine bottle,
  batteries, stuffed animal, spray bottle.

### A results (2026-11-19): criteria 1-3 met

The 588 test houses (583 with a mode-R target), three arms on one commit
(`4cfbee47`), on a cloud container, 4 workers, ~9 min. No call was made.
Rows, log and `score.json` are in `evaluations/room-prior-3190/a/`;
`tests/test_room_prior_set_3190.py` re-scores the rows and pins the verdicts.

| Prior | Found | Median goals | Median metres | Mean reward |
|---|---|---|---|---|
| Cloud (3.116.C's replies) | 573 | 5 | 15.6 | 0.515 |
| None (an unknown target today) | 573 | 5 | 19.2 | 0.415 |
| Wrong (top and bottom swapped) | 575 | 6 | 20.7 | 0.399 |

* **Criterion 1 (progress): met.** Paired reward cloud minus none +0.100
  [+0.051, +0.150], the interval wholly above 0; median goals 5 against
  none's 5 (bar: <=). The gain is in metres (-19% median), not in the whole-goal
  median. By category it gains on seven of nine (plunger +0.24, garbage bag
  +0.19, laundry hamper +0.15 on 13 houses, box +0.11, basketball +0.10,
  garbage can +0.07, house plant +0.03) and loses on cart -0.03 and dog bed
  -0.04, cart being 3.116.C's real disagreement with ProcTHOR's generator.
* **Criterion 2 (finds): met.** 573 against a bar of 567.27.
* **Criterion 3 (a wrong prior): met.** Found 575 against 561.54; median
  metres 20.7 against a bar of 24.0 (1.25 x 19.2). Its paired reward
  against none is -0.016 [-0.062, +0.030]: a wrong prior costs a little,
  without a settled loss. Not a bar: its median goals are 6, one over
  none's. As amendment 1 recorded, garbage can (149 houses) keeps bathroom
  tied at the top in this arm; its per-category figures are +0.04 there,
  and -0.18 cart, -0.11 plunger, -0.09 garbage bag where the swap is full.
  C may start.
* **Reported, the harness across commits:** the cloud arm reproduces
  3.116.C's found (573) but 67 of 583 rows differ from `c9/llm-R.json` in
  outcome, goals or metres (mean reward 0.515 against 0.508): the explore
  code has moved since `a5edad44`. Every arm here shares one commit, so the
  comparison is unaffected; 3.116.C's numbers are not re-stated by it.
* **Caveats, as written:** these houses are a fourth read of the test set,
  and they place objects by ProcTHOR's rules; for the nine categories the
  cloud's replies are not unknown targets but stand in for them. Whether
  the gain holds for targets outside ProcTHOR is what B's set (validity and
  sense) and E (a real house) can say; no sim house holds a spatula.
