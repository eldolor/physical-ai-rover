### A. The arrival's local-yes threshold: INTENDED, not a fault (A1 met)

No behaviour changed. The arrival is meant to stay on the module constant;
the tree's `local_yes_at` is for a frame's question only. The evidence:

* `3.94-tier-tree.md`, 3.94.D, "What a config may change":
  "`local_yes_at` (0.5), above `tier_local_no_below` and at most 1. It
  applies to the frame questions only."
* The same section, "What is fixed (hard rules, not settings)": "The
  arrival's own `LOCAL_YES_AT`: the found guard is 3.80.O's." and "A
  config that names any of these is refused as unknown."
* Its results: "`local_yes_at` 0.7 makes 0.6 unable for a frame question,
  while the arrival keeps 0.5."
* The suite pins it: `tests/test_tier_tree.py`
  `test_criterion_3_local_yes_at_moves_the_frame_question_not_the_arrival`.
* `config/robot.yaml`'s `tier_tree` comment: "local_yes_at 0.5 (frame
  questions, not the arrival) ... the arrival are hard rules and have no
  key."
* `docs/engineering/policy/ENGINEERING.md` already says both: the arrival
  confirms at "A score >= `LOCAL_YES_AT` (0.5)" (3.80.C), and the
  `tier_tree` row reads "`local_yes_at` 0.5 (frame questions only".

So the review's report (3.207, Batch 5) read a design decision as drift.
The spec needs no change. What would stop the next reader raising it again
is a comment at the comparison itself, and `brain/tiered.py` is fenced
(3.187.E). **For 3.187.E's holder,** above `if score >= LOCAL_YES_AT:` in
`_local_verdict()`:

```
# The module constant on purpose, not `self.local_yes_at`: the tree's
# setting moves a frame's question only; the arrival's found guard is a
# hard rule (3.94.D, 3.80.O; tests/test_tier_tree.py criterion 3).
```
