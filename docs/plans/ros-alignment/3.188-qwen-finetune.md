# 3.188 Fine-tune the local VLM (Qwen2.5-VL-3B) on real frames for frame identity

*`PLAN-ros-alignment.md` section 3.188; index: [README.md](README.md).*

**Why.** The user, 2026-11-17: "Work out a plan to fine tune the Qwen model
either using simulator outputs or real rover runs", then "Yes to both" (add
it to the plan; approve the GPU host for training at about $5-10, the
measured cost reported before anything more is spent).

**Real frames, not the simulator's.** `sim/renderer.py` draws flat-shaded,
untextured walls and writes objects as text labels; a VLM trained on them
learns the renderer. A photoreal simulator (ProcTHOR's own renderer) was
evaluated and parked by the user on 2026-10-22 and is not reopened here. The
simulator's role is the regression check in D.

**What is wrong today, and what is not** (recorded, not tested here):

* **Frame identity** (3.92, the pinned 2,261 frames): VE's yes-precision
  **94.9%** (bar 95%), recall 90.1%; 26 false yeses (grey backpack 12,
  charger cable 12), 53 in-view frames without a yes (basket 27, grey
  backpack 15). The errors are confident, not "unable" (the band holds 0.3%
  of frames). **This is what the section tries to fix.**
* **Arrival identity** (3.48 / 3.78, 299 frames): 97.2% precision, 1/34
  teal-bin lookalike frames a yes under INT4 AWQ. Must not get worse.
* **The box's bearing** (0.06 deg median from perception's): not touched.
* **Left/right direction** (3.80.F: `forward` on 40 of 40): not touched;
  explore chooses where to search (3.80.G).

**The risk this is built around: six objects.** The target is free text.
A model that learns these six and gets worse on a seventh is a loss, so
every accuracy judgement holds out whole objects (leave one object out).

**The gate from the 2026-10-22 survey** (approach 8: "only if Qwen fails
identity on the Rover's frames"). A and B run now on the phone frames to
learn whether a fine-tune generalises to unseen objects at all, which is
cheap. Nothing ships (C onward) before the stock model is measured on the
Rover's frames (E1).

## Design

* **Data.** 3.92's pinned set (`evaluations/tier-calibration-392/`, 21
  walks, 2,261 frames, 535 in view, six objects; "burgundy" and "red"
  backpack are one bag). Labels are the people's (`labels.json`'s
  `target_visible_labels`). **Never the cloud's answers as labels:** Opus 4.5
  scored 67.9% precision on 3.48's lookalike subset, worse than Qwen.
* **Folds** (`evaluations/qwen-finetune-3188/split.py` -> `split.json`,
  pinned by `tests/test_qwen_finetune_split.py`): six, each holding out every
  walk of one object. Fold training sets run 1,370-2,198 frames.
* **The question.** The identity question exactly as VE asks it
  (`tools/jetson/bench_identity_trt.py`'s template), the answer a single
  `yes` / `no`; the score is P(yes), as today.
* **Method.** SFT with LoRA on the language model (vision encoder frozen),
  every frame of the fold's five objects, both classes. GRPO (Visual-RFT;
  reward = a right yes/no) only by amendment, if SFT fails B's bars.
  Hyperparameters fixed in B1's script before the first fold runs and
  identical across folds; no tuning on a held-out object.
* **Like for like.** Each fold's fine-tune is compared with the **stock
  model in the same runtime** (BF16, transformers, the same GPU host, the
  same prompt and image size as VE: 128-512 image tokens). VE's numbers
  (INT4, the board) are context; the quantization's own drift is C's.
* **The 299 arrival frames** (3.48) stay out of training until A2 checks
  whether they overlap the 2,261; if they do, they are judged only by fold
  models that never saw their object.

## Criteria (written 2026-11-17, before any training; CLAUDE.md section 7)

**B, on the GPU host, each held-out object judged by its fold's model,
against the stock model on the same frames and runtime:**

1. **No object worse (stability):** on every held-out object, false yeses
   <= stock's, and recall >= stock's - 0.02.
2. **Fewer mistakes overall (progress):** pooled over the six held-out
   objects, false yeses + missed in-view frames at most **0.75 x** stock's.
3. **The precision bar:** pooled yes-precision >= **95%**.
4. **The worst object:** the grey backpack's yes-precision >= **90%**
   (stock VE 86.8%).
5. **Lookalikes:** 3.48's 34 teal-bin frames and 3.91 B4's 7 taupe-bag
   frames, each judged by a fold model that never saw that target: **0
   yes** (stock VE: 1/34 and 0/7).
6. **Cost reported:** GPU hours and dollars per fold, measured on the first
   fold; **the whole of B stops at $10** and reports before more is asked.

If 1-5 are all met, the all-objects model (trained on all six) goes to C.
A failed criterion is recorded as failed, not re-scoped.

**C, on the board (3.78's bars, unchanged), the all-objects model merged,
re-quantized to INT4 AWQ (calibrated on frames from the training set), the
17,920-token vocabulary kept, the Edge-LLM engine rebuilt:**

7. **Quantization drift:** the INT4 engine agrees with its own BF16 model on
   >= 98% of the 2,261 frames' yes/no.
8. Decision p90 <= **3.6 s** under the full stack; `MemAvailable` minimum
   >= **1,024 MB**, 0 OOM; perception p90 <= 250 ms; every nav2 goal
   succeeds (3.78.F's).
9. 3.48's arrival bars on the engine: precision >= 95%, teal bin 0/34,
   recall >= 50% (fold models' answers where a frame's object was trained
   on, by A2's rule).

**D, through the real path:** behind a config key naming the engine
(default the stock one): the simulator's tiered sweep keeps 3.46 criterion
1's safety property and its arrival rate; 3.91 B6's four walks replayed
through the ladder keep cloud calls <= B6's and lose no right yes; pinned
in a test.

**E, the Rover:** E1 the stock model on the Rover's frames first (owed by
3.80 / 3.92 anyway); if it meets 3.92's bars, the section stops there. If
not, A-D again on Rover walks with the household's objects and lookalikes
placed, labelled by a person (`label_assist`), held out by object.

## Amendment 2 (2026-11-28, before any paid job): how B is run, judged and stopped

Written by the worker that took B (the orchestrator's brief), before any
job was started; nothing below was chosen after seeing a number.

* **Code.** `b_manifest.py` (what each job trains on and is asked, from
  committed records; `--stage` puts presigned links in the deploy bucket's
  private `gpu-eval/qwen-finetune-3188/<stamp>/`, never in the repo),
  `b_job.py` (runs on the GPU, imports nothing from the repo, judges
  nothing), `b_launch.py` (start, bill, cancel; refuses a start whose
  timeout's worst case would carry the spend past $10), `b_score.py`
  (rows -> answers -> criteria), `b-spend.json` (every job and its bill).
  Pinned in `tests/test_qwen_finetune_b.py`.
* **The model and runtime.** `Qwen/Qwen2.5-VL-3B-Instruct` at revision
  `66285546d2b8`, BF16, transformers 4.51.3, SDPA attention, peft 0.15.2,
  on one `a100-large`. VE's image size (128-512 image tokens of 28 px).
  VE's grounding question (`bench_identity_llama.PROMPT`), greedy, at most
  64 new tokens, repetition penalty 1.0; the top 20 log-probabilities of
  the first 16 generated tokens from the raw logits. A reply is read with
  3.214's reader: `p_localised` the score, a yes at `LOCAL_YES_AT` (0.5),
  `parse_box` the box.
* **Training rows** (counts from `b_manifest.py`): the 2,261 less 3.206's
  200-frame draw and the 21 in-view frames without a kept 3.206.C label
  leaves a pool of **2,040 frames**. A fold trains on its five objects'
  frames of the pool, each **twice, as it is and mirrored** (the box
  mirrored in the student's pixels, `x1' = W - x2`, `x2' = W - x1`, `W`
  the width the model sees): folds 1-6 have 3,804 / 4,012 / 3,622 /
  3,732 / 2,756 / 2,474 rows, the all-objects model 4,080. Not in view:
  `[]`; in view: `[{"bbox_2d": [x1, y1, x2, y2]}]` from 3.206.C's label.
  Fold numbers follow `split.json`'s object order (1 the charger cable, 2
  the shoes, 3 the blue bottle, 4 the grey backpack, 5 the red backpack,
  6 the laundry basket).
* **Hyperparameters, fixed now, identical across folds, never tuned on a
  held-out object:** LoRA r 16, alpha 32, dropout 0.05 on the language
  model's attention (q, k, v, o) and MLP (gate, up, down) projections only;
  the vision encoder and merger frozen and adapter-free (the job refuses to
  train if an adapter lands on them). AdamW, learning rate 2e-4, no weight
  decay, cosine to 0 after a 5% linear warm-up, gradient norm clipped at
  1.0; one epoch over the fold's rows (so each frame is seen twice, once
  mirrored), 16 rows a step (8 x 2 accumulated); loss on the reply's tokens
  and its end-of-turn token only; bf16 autocast; **seed 3188** for the
  shuffle and the adapter's initialisation, the same for every fold.
* **What each model is asked.** A fold model: every frame of its held-out
  object in the 2,261, the mirror of that object's test-draw frames, and
  (the red backpack fold) the 7 taupe-bag frames. The stock model: the
  union, **2,468 tasks** (2,261 + 7 + 200 mirrored). The all-objects model:
  the test draw both ways and the 41 lookalike frames, reported only (it
  trained on the teal-bin walk as `[]`).
* **Order and stop rule.** (1) the stock run; (2) fold 1 as the pilot
  (train, save, ask); (3) folds 2-6 and the all-objects model. **Spend is
  each job's `runningSecs` from the jobs API, rounded up to whole minutes,
  at the flavour's per-minute price** ($0.041667 for `a100-large`, read
  2026-11-28); a job not yet billed counts at its timeout's worst case.
  After the pilot, the projection is spent + the pilot's training and asking
  time scaled by each remaining fold's rows and tasks + one start-up per
  remaining job; **a projection over $10 stops B and reports** before (3).
  A job that fails is billed and recorded; it is re-run once for a cause
  that can be fixed; a second failure of the same job stops and reports.
  The adapters go to the deploy bucket's private prefix (no frame is in an
  adapter's file, but it was trained on photos of the home: never to a
  Hugging Face repository, never committed).
* **How 3.188's criteria are read.** Each frame of the 2,261 is answered
  by the fold model that never saw its object; the stock model's answers
  on the same frames in the same runtime are the bars (criteria 1, 2, 4
  per object as written; "missed" an in-view frame without a yes). VE's
  numbers are reported beside them. Criterion 5: teal bin by fold 3,
  taupe bag by fold 5. Judged only on whole runs (every task answered, no
  error row).
* **How 3.206's criteria 4-10 are read** (its test set: 197 labelled
  frames, 163 unflagged, 34 `border` reported apart). A model's **own
  box** is its third (the box's centre, each edge clipped to the image the
  model saw) on a yes with a parsed box, else no answer. **The local
  order** is perception's detection, else the fold model's own box (as
  `a_set.local_order`, VE's place taken by the fold model). Criterion 4:
  own box right on >= 80% of the 163. Criterion 5: local order right on >=
  90% and above A's 85.28% by more than 5.44 points (so >= 148 of 163).
  Criterion 6: local order wrong-side <= 5. Criterion 7: a frame is
  consistent when its own box and its mirror's both give a third and the
  mirror's is the swap; >= 90% of the 163, with LEFT and RIGHT both among
  the answers. Criterion 8: per object, local order right >= A's on that
  object's unflagged frames. Criterion 9: 3.188's 1-5. Criterion 10: GPU
  dollars from `b-spend.json`; the teacher's dollars per kept label as
  3.214's measured 72B cost ($0.61 of pilots + $1.44 run) over 314.
  The stock model's own box and local order on the same test set are
  reported beside them.
* **What is committed:** answers (id, model, yes, score, box), scores and
  bills. Never a frame, a presigned link or an adapter.
