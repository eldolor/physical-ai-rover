# 3.194 A dock read late: a mission whose pose was unusable at its start still goes home

*`PLAN-ros-alignment.md` section 3.194; index: [README.md](README.md).*

**Why.** In 3.70.M2's live run, one find of five (row `k 3` of
`evaluations/find-last-seen-370/live.jsonl`) found its target and then did not go
home: `return: skipped, no_dock`. The mission's first status line was "no map
yet". The other four docked 0.070-0.089 m from the dock. 3.156's design (D1)
reads the dock once, at the start, and a robot that does not come back also
breaks the next mission's start (3.50.D: a reload localises from the dock).
Opened by the orchestrator on the user's delegation, 2026-11-20.

## The cause, traced (3.194.A)

`control/mission_runner.py` on `dev` `d291606c`:
* `read_dock()` (line 1232) turns the pose into a dock with
  `brain/dock.py` `dock_from_pose()` (line 103), which returns `None` for a
  pose with `usable: False`. `brain_server` calls it once before the start
  (`control/brain_server.py` line 1504) with the pose it read for the zones.
* `start()` (line 1268) reads it again only when that read gave nothing
  (line 1271-1273), then copies the answer into `self._dock` (line 1292).
  **Nothing writes `self._dock` after `start()`.**
* `_return_wanted()` (line 2413) answers `no_dock` when `self._dock is None`,
  so the whole mission has no trip home, however soon the pose comes back.

`world/ros_world.py` `get_pose()` (line 399) answers `unusable_pose()` on a
bridge error, before the session anchor exists, or on a stale map estimate
(`_stale`): the first seconds after a reload, or a moment under load (k 3's
run peaked at load 6.06 on 4 cores). Which of the three it was in k 3 is not in
the record (no brain log was kept); the mechanism is the same for all three.

**Reproduced in process** (`MissionRunner` -> explore -> `robot/safety.py` ->
`MockRobot`, `tests/test_dock_return.py`'s harness, a world whose first pose
reads are unusable): 0 unusable reads -> `docked`; 1, 2, 5 or 20 unusable
reads -> `found`, `return: skipped, no_dock`, every time. The robot drives off
on step 0 meanwhile, so the start pose is no longer the dock by the time a
pose is usable.

**What a dock read late may be (the design rule).**
* **The saved map's dock** (`source: saved_map`, a matched reload's pose
  carries it, 3.156.E) is a fixed point on the map's frame: it is the dock
  whenever it is read. k 3 ran on a reloaded map, so this is its case.
* **The start pose** (`source: start`, a fresh map or the simulator) is the
  dock only where the robot started. Read late, it is accepted only while
  the wheel odometry says the robot has not moved since `start()` (under
  0.05 m of path and 5 deg of heading, both readings usable); otherwise the
  return stays `skipped, no_dock`, never guessed (D1).
* Re-read at most once a second (the mission's clock) while the search runs,
  and once more when an end that goes home is decided. A dock found late is
  logged with how late, recorded in `status.dock` as `late_s`, and gets the
  start's other effects (D3's return reserve, E4's no-go split).

## Criteria (written before building; CLAUDE.md section 7)

| # | Metric | Bar | Kind |
|---|---|---|---|
| L1 | Red first: a test on `dev` whose pose is unusable for the first reads and then usable (a saved-map dock) | red on `dev` `d291606c`, green after; the mission ends `return: docked` within 3.156's bars (0.10 m, 10 deg) | progress |
| L2 | Sweep, delayed pose (in process; `scaled_house`, `home_first_floor`, `complex_house` x 10 spread starts x {find, survey} = 60 missions per arm; arms: the pose unusable for the first 1, 5 and 40 reads, a saved-map dock on the pose) | return rate: `return: docked` or a return that ran (`failed`/`cancelled` are 3.156's navigator's, recorded) in **100%** of missions whose dock became knowable before the end; `no_dock` in 0 of them | progress |
| L3 | No wrong dock, the same sweep plus a `start`-source arm (no saved dock: the robot drives off before the pose is usable) | every dock used within 0.01 m and 0.1 deg of the true dock (the saved dock, or the true start pose for `start`); a `start` dock read after the robot moved: **0** used | stability |
| L4 | The normal path unchanged: pose usable from the first read | 3.156's pinned suite green (`tests/test_dock_return.py`, `tests/test_dock_saved.py`, `tests/test_no_go_dock.py`, `tests/test_dock_navigator.py`, the live scorers); the 60 starts' outcomes, return states and docks identical to `dev`'s, mission by mission | stability |
| L5 | Live: the ROS stack, a reloaded map, a find started through the brain's HTTP API right after the reload | one find ends `return: docked` with `status.dock.source` `saved_map` | progress |

A missed bar is recorded as missed, not re-scoped. If L5 cannot be run in this
environment it is recorded as not run, with the reason.
