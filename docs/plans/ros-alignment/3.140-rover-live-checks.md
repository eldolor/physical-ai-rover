# 3.140 Live checks on the Rover and Jetson: everything built, tested on the car

*`PLAN-ros-alignment.md` section 3.140; index: [README.md](README.md).*

**Why.** The user (2026-11-01): "Add a section to the plan where we conduct
all kinds of live checks on the rover and jetson once the rover is
available. Everything needs to be tested on the rover, everything that's
been implemented on the plan." Development has been simulation-first
(CLAUDE.md section 2). Every built section was proved in the simulator,
under the fake board (3.25) and the fake lidar (3.42), on the Jetson in sim
mode (3.33-3.37, 3.71), or on phone and rig frames. None of it has driven
the Rover. The Rover-specific items are spread across about thirty sections
as "deferred to arrival", "waits on the Rover" or `[rover]` steps:
* 3.26's arrival list, 3.42 criterion 7, 3.73's measurements, 3.74's `[car]`
  criteria and 3.80.U;
* 3.81.F, 3.90.C-D, 3.116.D, 3.135.E, 3.136.E, 3.137.D-E and 3.50.D4b;
* `HARDWARE-READINESS.md` section 5, and section 6's decisions that wait on
  the car's numbers.

This section is the one place that walks all of it on the car. **Every
section 3.1-3.139 is accounted for below**: it gets a live check, or it is
listed as excluded, with the reason.

**What this section is not.** It does not re-decide any bar. A row's bar is
the source section's own bar, cited by number. Where the source has no bar,
the row is *reported*, and a bar for it is written in an amendment here
before that row's first run (CLAUDE.md section 7, rule 1). It owns no code.
A fix found here becomes its own section. The Rover-only steps that already
exist (3.80.U, 3.81.F, ...) stay in their sections, and this section
schedules them, it does not copy them.

**How the runs go.**
* The car is the Waveshare UGV Rover with the Jetson Orin Nano Super on its
  deck, `mode: hardware`, in the user's house.
* Every board run follows these rules:
  * The run holds the board lock (`board_lock.py run --why 3.140...`, 3.93),
    plus the desktop lock for timed runs (3.128).
  * The board is put back as found.
  * The run goes through the real path: brain -> `RemoteRobot` ->
    `robot/safety.py` -> `HardwareRobot`. It is never a harness that drives
    the motors itself (CLAUDE.md section 7, rule 2).
* Claude runs the missions and reads the logs. The user's part is only what
  needs hands:
  * placing objects and tape;
  * pulling a cable;
  * filming against the taped grid;
  * standing in a doorway;
  * keeping a hand on the Stop.

## Safety rules for every run (written before building)

1. **Wheels off the floor first.** Every new motion path (the first verb,
   the first `T:1` stream, the first nav2 goal, the first mission) runs
   first with the chassis on a stand. Only after that does it run on the
   floor.
2. **A person on the Stop.** Through levels L2-L5 a person holds the twin's
   STOP during every floor run. The physical power switch must be in reach.
3. **Safety is never off.** No run disables or bypasses `robot/safety.py`,
   the watchdog or the board heartbeat (rule 4). A check that needs a veto
   to "fail open" is done on the stand or in the simulator, not on the
   floor.
4. **Ground truth, not the veto's own readings** (CLAUDE.md section 6,
   "Judge any safety change on ground truth"). Distances come from a taped
   grid filmed from above (3.73's method), never from the lidar or the
   odometry being judged.
5. **Speed is capped low** (nav2 and the verbs at today's defaults) until
   L1's braking measurement (6.9(d)) and L2 pass. No speed is raised in
   this section.
6. **Stop on a surprise.** Any contact, unexplained motion, smoke, heat or
   brownout ends the session. It is recorded, and its row is FAILED.

## Criteria (written before building; CLAUDE.md section 7)

1. **Coverage.** Every section in the index 3.1-3.139 appears in the
   coverage table below, either with at least one row or as an exclusion
   with its reason. A section added after this one adds its own row here
   when it merges.
2. **Levels in order.** No row of a level runs on the floor before every
   row of the level beneath it has passed or been recorded FAILED with the
   user's go to continue. A failed L0, L1 or L2 row stops all later floor
   runs until it is fixed. A failed L3+ row does not stop the other rows.
   (Amendment 2: L4's floor runs wait on L0-L2 only, not on L3.)
3. **Source bars.** Each row is scored against the bar cited in its row,
   on one recorded commit of `dev`. A row is FAILED when it misses that
   bar, and it is not re-scoped. A *reported* row has its bar written here
   in an amendment before its first scored run.
4. **The real path, recorded.** Every row keeps its raw logs, the commit,
   the board's `/health` and the room. They go under
   `evaluations/rover-live-3140/<row>/`, never maps or images of the house
   in git unasked (CLAUDE.md, 3.50).
5. **Pinned.** Every number that sets a constant is pinned in a test when
   it lands in code (CLAUDE.md section 7, rule 3). That covers the
   xacro's `[PLACEHOLDER]` block, `track_scrub`, braking and the camera's
   field of view.
6. **Safety rules 1-6 above held on every run**, checked in each run's
   record.

## 3.140.A -- the harness (criteria written 2026-11-02, before building)

`evaluations/rover-live-3140/run.py` runs one row at a time on 3.136.A's
`boardrun.py` (the desktop lock, then the board lock; the commit pushed to
`~/bench-3140`; telemetry; fetch; the board put back as found). It never
drives the motors itself: a row's command is the brain's HTTP API or a
measuring tool, written by the step that owns the row (B-I). A ledger
(append-only) holds every run, its signed checklist, its verdict, the user's
go and the session's halts; the gates read it. It lives in the repository's
shared `.git` (`rover-live-3140/ledger.jsonl`: one for every worktree on the
desktop, as `plan-claims/` is), and each append is copied to
`evaluations/rover-live-3140/ledger.jsonl`, which is committed with the
records; a machine with no ledger starts from that copy.

A1. **The rows come from this file.** The runner reads the L0-L8 tables
    here: every ID once, in order within its level; an unknown row is
    refused. Nothing is copied into code.
A2. **Coverage (criterion 1)** is a command (`run.py coverage`): every
    section in the index 3.1-3.139 is in the coverage table, and every row
    it names exists; exit 1 otherwise. A section numbered after 3.140 that
    is in the index and not in the table is named, not passed.
A3. **The gates, each refusing before any board call**, each with a test
    against a fake ledger and board that fails with its gate removed:
    * (a) levels in order (criterion 2): a floor run at level N needs every
      row of levels 0..N-1 met, or (L3 and up) FAILED with the user's go
      (amendment 2: for L4, levels 0-2 only);
      while any L0-L2 row's latest verdict is FAILED, only that row's own
      re-run may run on the floor;
    * (b) stand first (rule 1): a floor run names its motion paths (`verb`,
      `wheels`, `goal`, `mission`), and each needs an earlier stand run of
      that path, closed with no surprise and not scored FAILED;
    * (c) a *reported* row with no bar in amendment 1 is refused (criterion
      3);
    * (d) the commit must be on `origin/dev` (criterion 3);
    * (e) the checklist (rules 1-6, below) must be signed, every item yes;
    * (f) a surprise ends the session (rule 6): closing a run with one
      scores its row FAILED and refuses every run until the user's
      `resume`;
    * (g) every board run (a `none` one too: a command can move the car)
      checks the board's `/health` first and refuses unless `mode` is
      `hardware` and `identity.git_revision` is the commit under test (the
      code that moves the car is the scored one).
A4. **Records (criterion 4).** Each run writes
    `evaluations/rover-live-3140/<row>/<run>/record.json`: the commit, the
    room, the surface, the motion paths, the checklist, the board's
    `/health` before and after, the raw logs, and boardrun's as-found check.
    Images, video and maps never enter git: the directory's `.gitignore`
    keeps them out, pinned by a test.
A5. **Locks.** A board run goes only through `boardrun.locked()` (desktop
    lock exclusive for a `--timed` row, shared otherwise; the board lock
    never waits) with `bench_dir="bench-3140"`; a manual row (hands and a
    ruler, no board command) takes no lock and records what was entered.
A6. **Amendment 1** gives every *reported* row a bar before any run, and
    `run.py check` reports 0 reported rows without one.
A7. Step A makes no Rover run and takes no board time.

The checklist a run signs (`--signed-by`; the person at the car):
1. stand runs: the chassis is on the stand, wheels clear (`--on-stand`);
2. floor runs: a named person holds STOP (`--stop-person`) and the power
   switch is in reach (`--power-switch`) -- for every floor run, L1
   included;
3. safety, the watchdog and the heartbeat are on, nothing bypassed
   (`--safety-on`);
4. distances are judged from the taped grid (`--truth grid`), or the row
   judges none (`--truth none`);
5. speeds are today's defaults (`--speed-default`);
6. after the run: `close --surprise no|yes` (a yes is rule 6).

The checklist, `go` and `resume` are a signed record of the named person's
answers, not a lock against the agent running the tool; an agent never
fills them with words the person did not give. A run is scored once, only
its row's latest run, and a run that raised can never be met. A stand run
counts for rule 1 only once it is scored met.
