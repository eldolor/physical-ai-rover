# 3.167 Inventory precision fell below 3.60's bar

*`PLAN-ros-alignment.md` section 3.167; index: [README.md](README.md).*

**Why.** 3.165 found it. 3.60's sweep
(`python -m tests.inventory_sweep --seed 3463`: 20 frontier missions in
`complex_house`, detector errors on) read **97.1%** precision of reported
when 3.60 merged (`87603bc1`, 2026-10-09), against a bar of 95%. On `dev`
of 2026-11-07 it reads **93.8%** (97 reported; 3.165's
`evaluations/inventory-3165/dev-sweep.json`). Recall moved the other way,
from 93.5% to 94.1%.

## 3.167.A: what counts as found (written before bisecting)

**Method.** `git bisect` from `87603bc1` (good) to `dev` (bad), one sweep
at a time under the shared desktop lock, with no other job of this
session's beside it.
* **The test:** each commit's own `tests.inventory_sweep --seed 3463`, run
  in a separate checkout. Its own harness is used, because the harness is
  part of what may have changed.
* **Good** is precision of reported >= 95% (3.60's bar); **bad** is below
  it.
* A commit where the sweep cannot run is skipped (exit 125).
* Each step's full score is kept (`evaluations/inventory-precision-3167/bisect.jsonl`).
* The endpoints are run first: if `87603bc1` does not read >= 95% today,
  that is recorded and the method stops for a rethink, not forced.

**Found** means all three of:
1. **The commit:** the first bad commit, with its score and its parent's,
   both runs recorded.
2. **A mechanism:** which landmarks turn from right to wrong, compared
   field by field between that commit and its parent (as 3.165 did), and
   why, traced to the lines that changed.
3. **A test that pins it:**
   * **If it is a bug:** a test that fails on the bad commit's behaviour
     and passes with the fix, red first, and the fix reviewed
     (`/code-review` + Thermos, Sonnet; the inventory is stored data). The
     sweep must come back to >= 95% with recall within 1 point of `dev`'s
     94.1%.
   * **If it is deliberate** (a later honesty fix in the simulator, a
     harness or detector change, a policy change that drives elsewhere):
     no "fix". Record the reason, and pin the mechanism in a test (the
     change's own effect, shown on a small case). Propose to the user to
     re-baseline 3.60's bar on today's numbers. Nothing is re-baselined
     here.

If the drop is spread over several commits (no single step from >= 95% to
< 95% explains it, or the bisect lands on a commit whose diff cannot touch
the sweep), that is recorded as the finding, with each step's score.
