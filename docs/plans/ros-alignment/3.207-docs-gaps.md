**How it is run** (the orchestrator, under the user's delegation,
2026-11-21):

* This section has no `## Steps` table on purpose. A step's Touches fence
  its paths from every other session, and these paths are the specs every
  code step must change in the same commit as its code (rule 6). So the
  section is claimed whole by the orchestrator, and each workstream below
  is one fresh worker session that edits only its own files.
* One session per section is the claim tool's rule, so the workers hold
  no claim of their own. Their files are disjoint by this table. A worker
  whose edit is refused by the claim hook (a path in another section's
  open step) stops and reports; nothing is worked around.
* Docs only. No code, config, test or template changes. A worker that
  finds the code wrong reports it; it does not fix it.
* Each worker pushes its branch, reports, and pushes to `dev` only on the
  orchestrator's word (the skill's section 3, item 5).
* No spending, no deploy, no force push.
