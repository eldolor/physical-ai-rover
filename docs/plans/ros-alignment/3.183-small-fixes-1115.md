# 3.183 Two fixes found in review: a stale slow-tier pin, capitalised room names

*`PLAN-ros-alignment.md` section 3.183; index: [README.md](README.md).*

**Why.** Two small faults found this week (the orchestrator, 2026-11-15):
* **A.** The slow-tier test
  `tests/test_walk_dist_sweep.py::test_every_walk_of_the_sim_surveys_gives_the_old_distances`
  fails on clean `dev`: its pinned label-call counts no longer match. Which
  merge changed them, and whether that change was intended, is decided and
  written down before the pin is touched; a regression is reported, not

* **B.** `brain/goal_policy.py`'s rooms policy keeps its prior under lower-case

  "Kitchen" (3.160.D's names) reads as no type and gets no prior (3.176.B's
  results).

**Criteria.** Each step writes its bars in this file before its change

## 3.183.A: the rule, written before the bisect (2026-11-15)

The test's first two assertions pin the 9 in-process `spacing` surveys
(`tests/survey_sweep.py`): every one `exhausted`, and each survey's label calls
as on `dev` at 3.120 (`[6, 6, 6, 33, 29, 28, 42, 44, 37]`). Its point (3.120
criterion 1) is the third: every `_walk_dist()` call during those surveys
equals the frozen `_walk()`. The label calls are a side record of the path the
surveys drove, so they move whenever exploration's choices move.

* **Find the merge.** Bisect `dev`'s first-parent history from 3.120.A's review
  (`528b0190`) to `dev`'s head, on the 9 surveys' outcomes and label calls,
  each commit run in its own worktree.
* **Intended** when that merge's section changed what a survey does by design
  (its goal choice, its stopping, its labelling), says so in its file, and
  re-pinned or measured the surveys it changed; then the pin is updated here,
  citing that section, with the new counts. An outcome no longer `exhausted`
  is judged the same way and recorded.
* **A regression** when no merged section meant to change survey behaviour
  (a refactor, a test-only change, a fix elsewhere): then nothing is
  re-pinned, and the step stops and reports.
* **The walk-distance assertion** (`bad == []`, `len(seen) > 50`) is run and
  recorded in either case; it must pass unchanged.

## 3.183.B: bars, written before the change (2026-11-15)

**The fault.** `RoomGoalPolicy.extend` keeps a goal's room type only `if t in
prior`, and the prior's keys are lower case (`__init__` lowers them), so a type
from a person's name "Kitchen" reads as unknown (3.176.B's repro prints
`['kitchen', None]`). A hint already matches without case (`hint_matches`).
**The change:** `extend` compares types without case (each type lowered before
the hint and the prior read it), and nothing else in the policy.

**Harness.** 3.160.D's sweep (`evaluations/room-names-3160d/sweep.py`: 3.116's
100 selection houses x modes R and U, `explore_goal_policy: rooms`, a person's
names standing in as each house's true room names), copied into
`evaluations/small-fixes-3183/` with one new arm, `names_title`: the same names
with each word capitalised ("living room" -> "Living Room"). The simulator's
names are all lower case, so 3.160.D's sweep never held a capital. Every arm is
run once on this branch and once from INSIDE a `dev` worktree (3.180's harness
flaw), and each record names the brain path it imported.

| # | Metric | Bar | Kind |
|---|---|---|---|
| B1 | A red-first unit test: a goal typed "Kitchen" (and "LIVING ROOM") gets exactly the room features of "kitchen"; a type the prior does not name still reads as none | fails on `dev`, passes after | stability |
| B2 | Lower-case names (`names`) and no names (`dev`): this branch against `dev`, 200 missions each | **0 of 200** differ in outcome, goals or metres, each arm | stability |
| B3 | Capitalised names (`names_title`) on this branch against lower-case names (`names`) on this branch | **0 of 200** differ: a capital changes nothing | progress |

**Expected effect, stated before the run.** On `dev`, `names_title` reads every
named room as unknown, so it should behave like a find with no room types at
all: its goals and metres should sit near the no-names arm, not the names arm
(3.160.D: mode R goals 9.78 with no names, 6.26 with names). After the change
it should equal `names` exactly (B3). `dev`'s `names_title` against `dev`'s
`names` is reported (the size of the fault), no bar.
