## 3.184.A: the set (written and frozen 2026-11-15; not scored)

`evaluations/request-blind-3184/requests.jsonl` holds 110 rows, `b001`-`b110`.

**Fields of each row:**
- `id`, `kind`, `text`, `names` (the saved map's room names; empty for most).
- `expect`:
  - `target`: the object phrase in lower case, or null for no target or two.
  - `room`: `{"type": t}` for a vocabulary type, `{"name": n}` for one of the
    row's names, or null. This is `room_hint`'s shape from 3.176.A's design.
  - `colours`: canonical, sorted.
  - `size`: `small`, `large` or null.

`tests/test_request_blind_set_3184.py` pins its sha256
(`0fe77d505a7619885b8b590df9e0869dd8879cebafad1277fb26d107e37cbb9f`) and its
shape:
- the row count in each kind;
- every room in the vocabulary or in that row's names;
- every target present in the sentence, in lower case;
- a null target exactly on the no-target and two-target rows;
- each colour and size word present in the target;
- no attributes without a target;
- 58 rows with a room and 52 without.

It imports nothing of the parser. A change to the set is an amendment
written here first, with the new hash.

**Kinds (16; rows in brackets):**
- plain (5)
- polite (9): greetings, "please", "for me", "thanks".
- indirect (10): "where did I leave", "I can't find", "I think I left",
  "it's in the study".
- room last (8)
- room first (6)
- synonym (11)
- relative places (12): under, behind, next to, beside, by, inside, near, and
  a room inside a furniture phrase ("the hall closet", "the kitchen
  counter").
- attributes (11): little/tiny, big/huge, gray, two colours joined by "and".
- a room word in the target (5)
- compound targets with "with" and "of" (3)
- typos (6): in the target, which is kept as typed, and in the room, which
  gives no hint.
- no hint (8): two rooms, a negation, outside the vocabulary, a place word.
- a person's names (5): a name wins over a type, matched whole and without
  case; a name outside the vocabulary.
- no target (3)
- two targets (3)
- case and punctuation (5)

**Decisions the rules did not settle**, written before any parser read the
set:
- **A room said before the target is read as a room.** Six `room_first`
  rows, e.g. "In the kitchen, can you find my mug?", expect `kitchen`.
  - 3.176.A's rule reads a room "in what follows the target" and says
    nothing of one said first.
  - People say it both ways, and the hint's purpose (what the person knew)
    does not depend on the order.
  - A parser that misses these fails P2 on them. That is a measured gap, not
    a defect of the set.
- **Owners of more than one word are stripped with the determiner.** "My
  daughter's backpack" and "grandpa's glasses" become "backpack" and
  "glasses", as 3.176.A strips "Ben's".
- **The target is the object phrase whatever verb asks for it.** "I think I
  left my phone in the den" gives `phone` / `living room`, and "Go to the
  garage and find the tape measure" gives `tape measure` / `garage`.
- **"near", "next to" or "by" a room names that room** (b053, b060). This is
  3.176.A's own decision, quoted from its rules, not a new one.
- **A colour or size word stays in the target as typed**, "gray hoodie" for
  example. The attribute is canonical (`grey`).

### Criteria: the fix's score on this set (the scorer runs once, in 3.184.B)

| # | Metric | Bar | Kind |
|---|---|---|---|
| P1 | target exact match (null for no target or two) | **>= 90%** (99 of 110) | progress |
| P2 | room exact match (type or name, or none) | **>= 95%** (105 of 110) | progress |
| P3 | a room given where none was expected, or the wrong room | **<= 1** of 110 | stability |
| P4 | attributes exact (colours compared as a set, and size) | **>= 95%** (105 of 110) | progress |

These are 3.176.A's P1-P4, with the same percentages and P3's same
absolute bound. P5 and P6 are 3.176's own set's and are not repeated here.

**Scoring rule.**
- The parser's `room_hint` is compared with `expect.room` as a dict. Target
  and room are compared exactly.
- The first full score of a parser on this set is the result. Any score after
  a change is reported only as a re-run, beside it.
- The per-row misses are recorded in 3.184.B's results. Whoever scores the
  set must not edit it.

**3.176.E's misses (2):**
- `b020` indirect, "I think I left my phone in the den". It expected `phone` / living room and got target `i think i left my phone`, with the room right. "I think I left" is not read as a request opening.
- `b036` room_first, "Check the bathroom for my razor". It expected `razor` / bathroom and got target `bathroom for my razor` and no room. "check the ROOM for X" is not read as a room said first.

**`dev`'s misses (13), for comparison**, the openings 3.176.E set out to fix:
- polite: `b006`, `b008`, `b009`, `b010`;
- indirect: `b020`, `b022`, `b023`;
- room first: `b033`-`b038`, all six. Three of them lose the room as well (`b034`, `b036`, `b038`).

**A caveat on P4** (from review): it is scored on every row, so a row whose
target is wrong but has no colour or size word still counts as attributes
right. Of the 110 rows, 11 carry an attribute, and both parsers get all 11
right. The 110 of 110 therefore says "no attribute lost or invented", not
"110 targets read".

**After the score, not re-run** (review): the scorer was hardened for any
later use, and none of these changes alters a count above.
- The set pin is now an explicit exit, not an assert, and the hash recorded
  is the one computed.
- It refuses a worktree that is not git, or whose `brain/request.py` differs
  from its commit.
- A parser that raises scores that row as a miss.
- It never overwrites an existing output.
- It records the parser as `brain/request.py` plus the commit. The two JSON
  files written by the one run still hold the scratchpad path.
- The hardened scorer was run once in memory against `761c2c4c` to check
  that it gives the same counts and the same miss ids. It did. Nothing was
  written, and that run is not a score.

The "room said first" decision, written before any parser read the set,
