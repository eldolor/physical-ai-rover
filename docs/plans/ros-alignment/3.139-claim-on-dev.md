# 3.139 Claims published on origin/dev

*`PLAN-ros-alignment.md` section 3.139; index: [README.md](README.md).*

**Why.** The user, 2026-11-01: "when you claim a section on the plan, you
need to push the plan to origin dev right away so that it's visible to all
other agents working on sections of the plan, so that you don't run into a
conflict where multiple agents end up selecting the same section of the
plan." Since 3.75 a claim is a file in the shared `.git/plan-claims/`, so
only worktrees on one machine see it; a step's State cell on `dev` stays
`open` until its section merges. On 2026-11-01 two sessions worked the same
step (3.137.A): one held a local claim, the other worked from an old plan,
and nothing on `origin` showed the step was taken. A second bug, the same
day: `plan_section.py release` run from one Claude Desktop session also
released 3.132.2, 3.132.4, 3.91.C and 3.96.C, other sessions' claims.

## Design (as amended by amendment 1, before building)

* **A claim is a branch on origin**, `claim/<step>` (`claim/3.137.A`; a
  whole section, `claim/3.139`). `claim <step>` makes a small orphan commit
  whose message names the holder (session id, worktree, branch, host,
  Claude pid and start, UTC time) and pushes it **create-only**:
  `git push --force-with-lease=refs/heads/claim/<step>: origin
  <sha>:refs/heads/claim/<step>` (an empty lease: the ref must not exist).
  Git's server takes exactly one; a rejection is a refusal naming the
  holder. The local claim file (3.75) is written only after the push
  succeeds, and records the claim's sha. Origin unreachable: `claim`
  fails; there is no local-only fallback.
* **`release`** deletes the branch with a lease on the sha it pushed, so it
  never deletes a claim someone has since replaced. With no step it gives
  back **this session's** claims only. `release --force <step>` deletes
  anyone's (the user's word only).
* **Ownership is the session** (`CLAUDE_CODE_SESSION_ID`) when both sides
  carry one, else the Claude process (pid and start) as before; the host is
  part of it. This is the release bug's fix: a no-step release used to drop
  every claim of the same `claude` ancestor and every claim whose owner
  read dead.
* **Stale claims.** Same host, holder process exited: anyone may take it
  over (delete with a lease on its sha, then create). Another host: never
  freed automatically; `board` shows `claimed (stale?)` once the claim
  branch and the section's plan branches have had no commit for 24 h, and
  says only the user may free it (`release --force`).
* **`board` / `next` / `claim`** read the claims on origin with one
  `git ls-remote origin 'refs/heads/claim/*'` (short timeout; objects of
  unseen claims fetched without touching any ref). `new` claims its whole
  section at once, which also reserves the number across machines
  (`used_numbers` counts `claim/3.N*` on origin).
* **Enforcement, blocking:** the commit hook refuses a commit on a
  `plan/3.N-*` branch without a claim of this session in 3.N (merges
  pass); the edit hook refuses an edit to a section file, or to a path in
  an open step's Touches, without a claim in that section (the ask/deny on
  another session's claim stays); the pre-push gate refuses a push to `dev`
  that changes a section file, or a path in an open step's Touches, of a
  section the pusher holds no claim in -- before the fast tier runs.
  `claim/*` pushes pass the pre-push hook untouched. Each refusal names
  `python tools/plan_section.py claim <step>`. One escape, for a person
  only: `PICAR_CLAIM_BYPASS=1`, which agents may never set.
* **No marker in the dev State cell** (amendment 1, point 2): see below.

## Criteria (written before building; CLAUDE.md section 7)

All in the fast tier against local bare repos as the origin (no test may
reach the real origin) unless stated.

1. **One winner.** 20 processes claim one step at once against a bare
   origin: exactly 1 winner (1 trial in the suite; 20 trials measured once,
   recorded here). Every loser's refusal names the holder, and no loser has
   a local claim file.
2. **Published first.** With origin unreachable, or the push rejected,
   `claim` fails and writes no local claim file.
3. **Seen from another machine.** A second clone with another host name
   sees the claim: `board` says `claimed` with the holder; its `claim` is
   refused.
4. **Release.** `release` deletes only a branch still holding the sha it
   pushed; a replaced branch survives. A no-step release by one of two
   sessions sharing one Claude process (different session ids) leaves the
   other's claims, local and on origin (the 2026-11-01 bug, red first).
   `release --force` deletes anyone's.
5. **Stale.** Same host, holder exited: claimable, and the new holder is
   published. Another host: refused whatever its age; shown
   `claimed (stale?)` after 24 h of no commits on the claim branch and the
   section's plan branches.
6. **Hooks.** Commit on `plan/3.N-*` refused without a claim in 3.N,
   passed with one, and passed for a merge; edit to a section file or an
   open step's Touches denied without a claim, allowed with one; the
   foreign-claim ask/deny unchanged; a push to `dev` changing a section's
   file or Touches refused without its claim and before the tier, passed
   for the holder; a `claim/*` push passes the real `pre-push` without the
   gate, and a push to `dev` still runs it; `PICAR_CLAIM_BYPASS=1` passes
   all three. Each refusal names the claim command.
7. **Cost**, measured live on this repo: the edit hook p90 under 300 ms
   over 20 calls (3.75's bar); one `claim` + `release` round trip on the
   real origin recorded.
8. **The real round trip** after merge: claim a step of this section, see
   `claim/<step>` on origin (`git ls-remote`), release it, see it gone.
9. **Nothing else breaks:** `test_plan_claims.py`, `test_review_376j.py`,
   `test_review_376i.py` and `test_plan_section.py` pass, changed only to
   give their scratch repos an origin.

## Amendments (written while building, before the run each affects)

1. **The lock is a claim branch on origin, not the dev State cell** (the
   user, through the coordinator, 2026-11-01, before any code). The first
   design pushed a `claimed (...)` marker into the step's State cell on
   `dev`. Dropped, and with it any dev marker (point 2 asked for one only
   if it is cheap and never conflicts; it is neither):
   * the holder's own `done (...)` edit and dev's `claimed (...)` change
     the same line from the same base, so every finished step would
     conflict when its branch rebased;
   * every dev edit of a section file makes the board read dev's table
     instead of the branch's (`_dev_moved`), hiding the branch's new rows;
   * a new section's rows are not on dev at all;
   * each claim would cost a dev commit and a docs-only gate run.
   A `claim/<step>` ref is atomic on the server (create-only lease), costs
   no gate, and never touches a file a branch edits. `board` is the view.
2. **Criterion 9's tests change in two places, not only by an origin.**
   `test_criterion_4_the_edit_guard` asserted silence on `control/x.py`,
   which is in 3.91.A's Touches: under the new rule that path needs a claim
   in 3.91, so the "unclaimed path" check moves to a path in no step.
   `test_criterion_2_a_reused_pid_does_not_keep_the_claim` tampered only
   the local file's start; origin's copy now names the holder too, so the
   test tampers both (a reused PID is one on both).
3. **Two holes found on this repo's own tables while building, before any
   recorded run.** (a) 3.138.B lists `CLAUDE.md`, so every merger's status
   edit (rule 3) would have been refused: the shared status files
   (`CLAUDE.md`, `docs/ARCHITECTURE.md`, the index, `PLAN-ros-alignment.md`)
   are never fenced by Touches. (b) A file two sections' steps list was
   refused to the holder of one of them: the pusher's (or editor's) own
   section's Touches, as pushed, cover it. Both red first.
4. **The section-start board runs in cloud sessions too**
   (`.claude/hooks/plan-board.sh` skipped them: their claims were invisible
   then; now origin holds them).

5. **Origin is a public repository** (found in review): a claim's message
   carries the worktree's folder name only, and the host and session as
   digests (`h-...`, `s-...`), never the host name, a home path or the raw
   session id. The host digest includes the pid namespace, so two
   containers sharing a host name are two machines.
6. **Waiting and blocked steps fence nothing** (Thermos round 1): only an
   open step with no Waits and its Needs done fences its Touches. Before
   this, `tests/`, `control/` and `web-twin/` were fenced by steps nobody
   could claim.

**Bootstrap.** `new` (3.139 itself was reserved by `dev`'s old `new`) does
not yet claim; the hooks only start biting once this branch's
`plan_claims.py` exists. Order used: tests written and committed red under
the old code; the whole new `plan_claims.py` written in one step; then at
once `claim 3.139` (whole section) on the real origin, before the next
commit, which the new `pre-commit` checked and passed. The edit hook of
this session runs this worktree's file, so every later edit was judged by
the new code and passed on that claim. After the review made holders
public-safe, the old-format `claim/3.139` (raw host name and path) was
replaced: `release --force 3.139` (this session's own, which the new
ownership no longer recognised) and `claim 3.139` again. The old orphan
commit stays reachable on GitHub only by its sha until GitHub collects it.

**Review.** `/code-review` (high) and the Thermos bug pass on the branch,
then `/code-review` again on the fixes. Confirmed by both: (1) a claim of
another session in the same live `claude` process read as an "earlier
conversation" and was taken over or released -- now a live process's claim
always holds; an earlier conversation's is freed by the user; (2) the hooks
trusted the local file -- the push gate now counts a claim only while origin
holds it (the commit and edit hooks stay local: one network call per edit
is too slow; recorded limit). Found by one, checked and fixed: two
machines could both win one section through two refs (a re-read after the
push; a rival means back off, and `new` retries the number after a pause);
cloud containers sharing a host name (host digest with the pid namespace);
a session lost its claims when its machine renamed itself (session ids
compare across hosts); `new` left a branch on a non-SystemExit failure; the
session-start board waited up to 40 s (5 s now); the published holder
carried the host name, home path and session id to a public repo; waiting
and blocked steps fenced half the tree; a missing base passed or crashed
the gate (fails closed); a failed re-check withdrew a won claim (kept, with
a warning); unreadable holders read as someone else's (an error now); the
hook's stdin session id disagreed with the environment's (one source:
the environment). Not taken: the explicit `claim/*` case in `pre-push` is
redundant with the dev-only check, kept because it states the rule.

**Open items.**
* The commit and edit hooks read the local claim file; a claim freed on
  origin from another machine still passes them until the push gate.
* A step whose Needs are only on a plan branch (not yet on dev) does not
  fence its Touches (`quick_steps` reads dev plus the current branch).
* A claim from another host (or a cloud container that restarted, which is
  a new pid namespace) is never freed automatically; same session id still
  owns it.
* `new` now needs a Claude Code process (or `PICAR_CLAIM_PID`) and origin.
* Claims made before 3.139 carry over locally for the commit and edit
  hooks, but the push gate refuses until the session re-runs `claim <step>`.
* The release bug's cause was not reproduced (each Desktop session here
  runs its own `claude` process); the fix removes both possible causes: a
  no-step release now drops only this session's claims, never a dead
  owner's or the same process's.
