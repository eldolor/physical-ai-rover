# 3.223 The board drives the pan-tilt servos but never reads them

*`PLAN-ros-alignment.md` section 3.223; index: [README.md](README.md).*

**Why.** On the Rover the ESP32 board moves the pan-tilt servos but never
reads their positions (3.220 criterion 6, 2026-11-26). Each `T:133` moves
the camera and the servos hold torque, so the board's writes reach the
servo bus. But with module type 2 (`T:4 cmd 2`) every `1001` frame
reads `pan` -179.96 and `tilt` +179.96, which is servo position 0, the
firmware's initial `gimbalFeedback`: `st.FeedBack(id)` never succeeds
for IDs 2 or 1 (`gimbal_module.h getGimbalFeedback()`, Serial1 at 1 Mbaud
on GPIO 18/19). The loop then slows from 50 to ~219 ms (two read timeouts
each loop) and the board's web route times out, so the wheels refuse all
motion. 3.220 refuses a camera frame without a measured pan, so
`ROBOT_GIMBAL` stays off on the Rover and the twin's look and tilt buttons
cannot be used there.

**What is known.** The servos obey commands, and the pan and tilt signs
are both +1, watched. The same board's serial receive from the Jetson is
also dead (3.217, the reason commands go over Wi-Fi), so its receive
side may be at fault, not the servos. Not yet tried: a power cycle of
the board, reseating the servo bus cable, a read of one servo by
Waveshare's own tools, and asking Waveshare (only on ticket 263625, and
only on the user's word).

**Done means:** either the board reads both servos (3.220 criterion 6
re-run, all of it), or a decision by the user on what replaces the
measured angle.

**Criteria (written before building; CLAUDE.md section 7):** to be written
by the first step, before anything is measured.
