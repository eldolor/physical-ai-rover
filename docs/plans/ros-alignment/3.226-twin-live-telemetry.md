# 3.226 The twin's Drive page shows live system data: battery, Wi-Fi command loss, refusals, the trip-home estimate, retrace room

*`PLAN-ros-alignment.md` section 3.226; index: [README.md](README.md).*

**Why.** On 2026-11-27, during 3.224's supervised surveys on the Rover,
the user asked to see live odometry, battery and other system data on the
twin's Drive page. Today the twin shows: an odometry readout on Drive
(Engineer mode only), a battery banner that appears only at Low, Reserve or
Power-off (its volts line only then, Engineer mode), and the brain panel's
"Last refusal". Everything else a person supervising a run wants was read
from the board by hand (`/health`, `/mission/status`): the battery voltage
while ok and its sags, Wi-Fi command loss (`motor_board.command` sent and
failed), refusal counts by reason (`refusal_counts`, `last_stop_reason`),
the trip-home estimate (`budget.home`: metres and seconds home, measured
drain, the reserve's margin), the retrace room (3.224), the wheel loop's
late ticks, and `drive` (ROS up, bridge up). The data is already on the
wire; the gap is the page. Step A writes the bars (which fields, operator
vs Engineer mode, refresh rate, the 390 px phone layout) before any code;
a phone-size screenshot is the evidence (CLAUDE.md section 7).
