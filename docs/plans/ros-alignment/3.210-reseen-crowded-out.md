# 3.210 A re-search's places crowded out by later false sightings

*`PLAN-ros-alignment.md` section 3.210; index: [README.md](README.md).*

**Why.** 3.192.B's C1 (the re-search of places a find saw the target) left
`procthor:val:44` s0-s2 `exhausted` in the rooms chooser's no-zone arm
(3.192.B C2's record, `evaluations/nogo-3192/fix/find_rooms.json`), while
the rule arm and the rooms+zones arm find it. No step owned it.

**Trace (2026-11-21, `dev` f8fa8ef, which includes 3.205.A 0157d902 and
3.198 3d3e344f; neither changes it).** In process, `sweep_c1.py`'s `run`
unchanged, the rooms chooser, arm `none`. The arm places no zones, so the
seed changes nothing: s0, s1 and s2 are one mission (all three rows read
`exhausted`, 770.6 s, 37 goals, 1 round, 3 places). Reproduced exactly. The
backpack is at (9.45, 2.55).

* t = 381.5 s: a sighting at **(9.48, 2.69), 0.14 m from the target**,
  seen from (9.75, 5.85). Approach goal (9.15, 3.15) sent; `_seen_at` =
  [that place].
* t = 383.5 s and 385.5 s: two **false** sightings, (7.19, 5.78) and
  (8.99, 5.25), 3.95 m and 2.74 m from the target, each ranged 0.16-2.3 m
  from the robot. Each moved more than `APPROACH_MOVED_M`, so each
  superseded the live approach (`brain/explore.py` lines 612-617). This
  supersession is older than 3.192 and happens in the arms that find it too.
* t = 724.2 s: a fourth, (8.91, 4.19), 1.73 m off, seen from 0.17 m.
* t = 755.4 s: the frontiers ran out. `_reseen_places` (`brain/explore.py`
  lines 1076-1086) hands up the **latest** `RECALL_MAX` = 3 of the 4 kept
  places: `reseen` with places [(8.91, 4.19), (8.99, 5.25), (7.19, 5.78)],
  `kept_of` 4. The one true place is the oldest, and it is dropped.
  `_choose_next` then clears `_seen_at` (line 1460), and a second round
  runs only on new sightings. None came, so the find ended `exhausted` at
  770.6 s with the target's place known and never looked at again.

The arms that find it reached a view goal (8.55, 3.15) looking west and
re-sighted the target from there. The route got them there, not C1. The
rooms+zones s2 row fired 2 rounds and found it.

**The defect.** C1 is meant to stop a find giving up on a target it saw
(3.192.B amendment 3). Its cap of 3 a round, taken latest first, plus the
clearing of what was kept, throws away seen places that it never looks at.
That is still giving up on a seen target, as long as later false sightings
outnumber it.

**Probe (a scratchpad monkeypatch, not built).** Letting round 2 take the
places round 1 left out, with the same caps (2 rounds, 3 a round), finds
val:44 s0 rooms/none: **`found`, 790.6 s**, 40 goals, 2 rounds, 4 places.
`val:26` s0 rooms+zones, the other row C1 left `exhausted`, is unchanged
(`exhausted`: it already uses 2 rounds and 6 places, a different case, not
this section's).

**The proposed fix (D1), in `brain/explore.py` only.** At the round's
hand-up, the kept places it does not hand up stay kept. A second round runs
on sightings since the first **or** on places kept but not yet looked at,
latest first. Nothing else changes: at most `RESEEN_ROUNDS` (2) rounds and
`RECALL_MAX` (3) places a round, never a survey, never a refused place.
Nothing changes before the first `reseen` either, so every mission that
does not reach C1's re-search runs identically. Neither does a mission
whose first round held every kept place.

**Criteria (written before building; CLAUDE.md section 7).** Harness
unchanged: `evaluations/nogo-3192/fix/sweep_c1.py`, both choosers, both
arms, 96 finds an arm and 12 surveys, `SWEEP_WORKERS=4`. Plus a broad
progress sweep beyond those 32 houses: `tests/procthor_sweep.py`'s next 60
usable val houses after the first 30, 3 seeds, red backpack, rooms chooser,
no zones, through the same `run` (`evaluations/reseen-3210/broad.py`). Each
arm is paired with a fresh `dev` control from a clean worktree.
