# 3.212 Every live run keeps its full ROS, robot and brain logs beside its rows

*`PLAN-ros-alignment.md` section 3.212; index: [README.md](README.md).*

**Why.** The live harnesses write their logs into the run directory that
`tests/demo_explore._new_run_dir()` makes under `EXPLORE_LOGDIR` (by default
`/tmp/vision-picar-3.N`). A cloud container is reclaimed after its session,
so the logs go with it and only the rows are committed. Three traces have
hit this:
* 3.70.M3's trip home ended `nav2_aborted` and could not be traced: its
  brain and ROS logs did not survive (3.204, 3.211).
* 3.211 committed a filtered excerpt of its ROS log. The excerpt then misled
  the next reading: mask lines that follow a planner failure were read as
  its cause.
* The keepout trace (3.211's "Corrected", 2026-11-22) could not classify
  some mask lines, because the full log was gone.

The orchestrator opened this under the user's delegation (2026-11-22), after
the keepout trace.

**The design.**
* `tests/demo_explore.py` notes every run directory its process makes.
* A new `keep_logs(dest)` copies each run directory's top-level `*.log`
  files, gzipped, into `dest/<run-dir-name>/`.
* It copies only regular `*.log` files directly in a run directory. It never
  copies a subdirectory (`maps-*`, `inventory-*`), any other file, or a
  symlink. Maps and inventories are a home's floor plan (CLAUDE.md section 6,
  "Live runs"), so they never leave `EXPLORE_LOGDIR`.
* **Two ways in:**
  * `evaluations/find-last-seen-370/live.py` (the 3.70.M2/M3 harness that
    3.205 and 3.211 used) calls it in its `finally`, after the container's
    last log is saved. The destination is `<rows stem>-logs/` beside the
    rows.
  * Any other harness gets it through one environment variable,
    `PICAR_KEEP_LOGS=<dir>`, which registers an `atexit` hook. There are
    about 30 harnesses on `de.RUN_DIR`, and none of their code changes.
* No ROS, safety, brain or server code changes. Only a test helper and one
  harness do.
* **Committing the kept logs is the session's call, as the rows are.** A
  real house's logs name poses in that house, so on the Rover they are
  reviewed before anything is committed.

**Criteria (written before building; CLAUDE.md section 7):** the bars are
judged on a synthetic run directory in the suite. This step runs no live
stack (see "What A cannot show").

| # | Bar | Kind |
|---|---|---|
| A1 | Every regular top-level `*.log` of every run directory the process made is kept at `dest/<run>/<name>.gz`, and gunzips byte-identical: **all of them**, on a normal end and on an exception inside `live.run`'s `try` | progress |
| A2 | Nothing else is copied: **0** files from a subdirectory (a planted `maps-x/` and `inventory-x/`), 0 files that are not `*.log` (a planted `.pgm`, `.json`, `.yaml`), 0 symlinks (a planted `evil.log` pointing at a map) | safety of data |
| A3 | A failed copy (an unreadable file, a destination that cannot be written) **never raises** out of `keep_logs`, never replaces the run's own exception, and is reported on stderr with the file it lost | stability |
| A4 | Never overwrites: an existing `dest/<run>/` is kept, and the new copy goes to `dest/<run>-2/` (the rows' own rule: "never overwritten") | stability |
| A5 | `PICAR_KEEP_LOGS` unset: nothing is registered and nothing is written (every harness as before). Set: the `atexit` hook keeps the logs at process exit, shown by a subprocess test | stability |
| A6 | The fast tier passes | stability |

**What A cannot show:** the size of a real run's kept logs, and that a real
run keeps them. A live run costs an hour of the 4-core container at a load
above 4, so none is run for this harness change. The next live run of
`live.py` is the check: its `<rows>-logs/` directory holds `ros-s1`,
`ros-end`, `robot-*` and `brain-*` (each `.gz`), and its sizes are recorded
then.
