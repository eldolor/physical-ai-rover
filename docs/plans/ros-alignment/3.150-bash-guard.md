# 3.150 A Bash hook refuses the gate bypasses and a branch's :latest image

*`PLAN-ros-alignment.md` section 3.150; index: [README.md](README.md).*

**Why.** Three rules are the user's alone or nobody's, and today only prose
and git hooks hold them:

* `PICAR_SKIP_GATE=1` and `PICAR_CLAIM_BYPASS=1` are the user's escapes
  from the push gate and the claim hooks (CLAUDE.md 3c,
  `PARALLEL-SESSIONS.md` rule 12). The git hooks honour them, so a session
  that sets one is let through.
* `--no-verify` on `git push` or `git commit`, or a `core.hooksPath`
  override, skips those git hooks altogether.
* `vision-picar-ros:latest` is shared by every session's live runs; it is
  rebuilt only from `dev` ("never rebuild `:latest` from a branch", 3c).

A Claude Code PreToolUse hook on `Bash` sees the command before it runs and
can refuse it with a reason the session reads. Proposed by Claude, accepted
by the user on 2026-11-04 (with the guard failing closed).

**Design.**

* `tools/bash_guard.py hook`, wired in `.claude/settings.json` beside
  `plan_claims.py hook-edit`. It reads Claude Code's hook JSON on stdin.
* It splits the command into simple commands (`;`, `&&`, `||`, `|`, `&`,
  newlines, parentheses; heredoc bodies and comments are not commands) and
  refuses:
  1. an assignment `PICAR_SKIP_GATE=1` or `PICAR_CLAIM_BYPASS=1` before a
     command, after `env`, or in `export`;
  2. `git push`/`git commit` with `--no-verify` (or commit's `-n`), any git
     run with `-c core.hooksPath=...`, and `git config core.hooksPath`;
  3. `docker build`/`docker buildx build` tagging `vision-picar-ros:latest`
     (or the bare name, which means `:latest`) unless the directory the build
     runs in (the hook's `cwd`, then any `cd` earlier in the same command) has
     HEAD at `origin/dev`'s commit and no changes, tracked or untracked,
     under `service/slam/`; and `docker tag` onto it, always.
* A refusal is the edit hook's: `ask` where Claude Code shows the user a
  question (`default`, `plan`, `acceptEdits`), else `deny`, with the rule
  and "the user's call" in the reason.
* **Failing closed:** if the command cannot be parsed, or the check raises,
  a command whose text names a guarded word (`PICAR_SKIP_GATE`,
  `PICAR_CLAIM_BYPASS`, `no-verify`, `hooksPath`, `vision-picar-ros`) is
  refused; any other command passes. The settings line runs the script
  only if it exists in the checkout, so a checkout from before 3.150 is not
  blocked. A seatbelt for honest mistakes, not a sandbox: a script file run
  by `bash x.sh` is not read.

**Criteria (written before building; CLAUDE.md section 7):**

1. **Refused:** a table of at least 25 commands that break a rule above,
   including compound ones (`cd x && PICAR_SKIP_GATE=1 git push origin
   HEAD:dev`), `env`/`export` forms, combined short flags (`git commit
   -anm x`), `--tag=` and `-t` forms, and a `:latest` build from a branch
   checkout -- every one refused (`tests/test_bash_guard.py`).
2. **Passed:** a table of at least 25 ordinary commands, including ones
   that name a guarded word without breaking a rule (`grep -n
   PICAR_SKIP_GATE tools/hooks/pre-push`, a heredoc writing a doc that
   mentions it, `git push --dry-run`, `git push -n`, `docker build -t
   vision-picar-ros:plan-3.150 service/slam`, a `:latest` build from a clean
   `origin/dev` checkout) -- every one passed.
3. **Red first:** the refusal table fails against `dev`'s settings (no Bash
   hook): the test that runs the settings' own command line on each row is
   written and seen failing before the hook is wired.
4. **Fails closed:** an unparseable command naming a guarded word is
   refused; one naming none passes; a check that raises (injected) refuses a
   guarded command and passes another; stdin that is not JSON passes unless
   it names a guarded word.
5. **Ask or deny:** `ask` under `default`, `plan` and `acceptEdits`; `deny`
   under `auto`, `bypassPermissions` and a missing mode.
6. **Live:** in this session (auto mode), one real Bash call of a refused
   command (`PICAR_SKIP_GATE=1 true`) is denied by Claude Code with the
   reason, and one ordinary call runs.
7. **Cost:** the hook adds at most 150 ms p90 to a Bash call (100 runs of
   the settings command on an ordinary command, on the desktop).
8. Reviewed (`/code-review` and, as `tools/` hooks are on the risky list,
   the Thermos pass); `ready` passes.

**Results (2026-11-04): criteria 1-5, 7 and 8 met; 6 FAILED as written
(owed to the next session).**

1. Met: 108 refused rows (`REFUSED` in `tests/test_bash_guard.py`), plus
   the `:latest` checkout cases, every one refused.
2. Met: 68 passed rows, plus a `:latest` build from a clean `origin/dev`
   checkout (with a redirect or flag after it), every one passed.
3. Met: against `dev`'s settings (no Bash hook) 78 of the first 80 tests
   failed. Each review round's rows were red on the round before: 32, 24,
   17 (one hung past 30 s), 7, 8.
4. Met: unparseable and raising cases refuse only commands naming a bypass,
   a hook skip, or the shared image beside a writing docker verb; non-JSON
   and non-object stdin pass unless they name one.
5. Met: `ask` under `default`, `plan`, `acceptEdits`; `deny` under `auto`,
   `bypassPermissions`, `dontAsk` and a missing mode. `ASK_MODES` is pinned

6. **FAILED as written.** `PICAR_SKIP_GATE=1 true` ran in this session:
   Claude Code reads hooks at session start, so a hook added mid-session
   does not run in it. The next session started on `dev` owes the check

7. Met: p90 27.5 ms (round 0, load 0.9), 32-40 ms (round 4), 88-100 ms on

8. Met: `/code-review` five rounds, the Thermos pass three (rounds 1-3);

**The design moved with the data (amendments, before each round's run):**

* **The transcript corpus.** Every distinct Bash command in this
  machine's Claude Code transcripts for the repo (8,774-8,844) through the
  hook, in ~3 s. Round 2's hook refused 30. Eighteen were legitimate
  `git push --no-verify` of other refs (plan branches to origin or the
  Jetson, branch deletions under rule 11), and `tools/hooks/pre-push` gates
  only `refs/heads/dev`. So `--no-verify`, and a `core.hooksPath`
  override on a push, are refused only when the push can reach `dev`: a
  `dev` destination, `--all`/`--mirror`, a glob matching it, a bare push
  while on `dev`, or a refspec variable it cannot resolve (a literal
  `for b in ...` or `B=...` earlier in the command is expanded). On a
  commit they are always refused; a `core.hooksPath` override on
  `stash`/`worktree` passes (tools/hooks has no hook there).
* **The final corpus: 10 refused of 8,844, worst 6 ms a command.** 2 true
  (a session's `PICAR_CLAIM_BYPASS=1` push, this section's own live test);
  6 legitimate `:latest` rebuilds in an `origin/dev` worktree the same
  command creates (the hook cannot check a checkout that does not exist
  yet; the reason says to create it in one call and build in the next); 2
  `-c core.hooksPath=/dev/null commit` of a planted red test on a scratch
  branch (3.121, never pushed): refused, so that session would have asked.
* **Remote commands.** `ssh host 'CMD'` and heredocs fed to `ssh` are read
  for bypasses and hook skips; docker tags there are not checked, since the
  board rebuilds its `:latest` from `git archive origin/dev` with no
  checkout to check.

**Known limits (recorded, not fixed):** a script run from a file;
`source <(...)` or `eval` of generated text; a `cd` inside `( ... )`
leaking into later commands; `case` patterns and arithmetic read by
heuristics; a variable set outside the command. A seatbelt, as the design
says.

**Review rounds.** 1: 12 holes, 2 false refusals (the first tokenizer let a
comment line hide every later line). 2: substitutions in double quotes,
heredocs fed to a shell, redirections read as a build context (a false
refusal both reviewers found). 3: an exponential scan of nested
substitutions (5 s at 18 levels; now 6 ms at 40), `case` inside `$(...)`,
`ssh` arguments, `git -C`, `--repo`. 4: round 3's own regressions, 10, most
false refusals through the fail-closed path, which was narrowed. 5: no
false refusal, no crash or hang; 8 refusals round 4 had lost, fixed.
