# 3.186 Harnesses load the robot code they name, not the launch directory's

*`PLAN-ros-alignment.md` section 3.186; index: [README.md](README.md).*

**Why.** (the user, 2026-11-15, through the orchestrator; found by 3.180's
candidates.) `evaluations/explore-365/harness.py` line 14 (and
`classify_lost.py`, `evaluate.py`, `time_choice.py`, `train.py`,
`train_net.py` there) does `sys.path.insert(0, ".")`. Every script that
imports it -- directly, or through `goal-learn-396/train.py` or
`goal-tap-388/oracle.py`, about 30 harnesses and tests -- then loads
`brain/`, `control/`, `sim/` and `world/` from the directory it was LAUNCHED
in, whatever checkout `REPO` (or the script's own path) names. 3.180.A's
first baseline ran its branch's brain as "dev" this way. Two merged results
whose `dev` arm went through it cannot say where they were launched:
3.160.D's D4 and 3.116.B's criterion 7.

## 3.186.A: criteria (written 2026-11-16, before any code)

**The change.** The six `explore-365` files put their own checkout's root
(two directories above the file) first on `sys.path` instead of `"."`.
`harness.py`, which every exposed harness imports, also records the brain it
loaded (`harness.BRAIN`, and a `brain: <path>` line on stderr at import) and
refuses (`SystemExit`) when `brain` resolved outside its own checkout. No
product code changes.
