What the drills prove
The two failsafes that matter most on hardware cannot be provoked by pressing anything — you would have to unplug the internet at the right moment. A drill breaks exactly one thing and leaves every other guard standing, so what you watch is the real failsafe firing: the mission ends, the reason is named, and the robot is stopped. The watchdog readout above is the third one (robot/server.py): it counts how long the robot has gone without a command, and stops the motors on its own if that passes the timeout.

Setting this up
When this page is served by the robot server itself, the URL above is already filled in to match — add the shared secret if the deployment requires one and tap Connect. Setting this up
Run uvicorn control.brain_server:app --host 0.0.0.0 --port 8001 alongside the robot server — on the Pi in the finished robot, on any machine during development. It reaches the robot over HTTP too, so the two do not have to share a machine; brain.robot_url in config/robot.yaml is the only thing that decides where it looks. On a Pi/MacBook dev setup this usually shares the robot connection's secret above (both processes read the same APP_SHARED_SECRET), but the two can be independently deployed with their own generated secrets (e.g. two separate ECS services) — this field is always sent as-is, never assumed to match the one above.
